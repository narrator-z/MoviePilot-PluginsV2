# 2026-08-05 工作日志

## StuckDownloadGuard（下载守卫）新增「降级切换」v1.1.0
- 用户反馈：下载守卫没实现「长期下载速度=0 自动降级切换」功能（"下载卫视"为"下载卫士"同音笔误）。
- 核查现状：原插件有「降级排至队尾」（队列重排，对无源0速度无效）+ 阶段二「停止+清理+订阅重搜」（仅订阅源、且埋在 max_retries 次之后）。真正的「切换下载源/种子」缺失。
- 实现：
  - `__handle_stuck` 重写 —— 每次卡顿先降级排尾，再尝试切换源（每周期仅一次）；切换成功即移除原种子；切换失败且达 `max_retries` 则停止清理。
  - 订阅源：`SubscribeChain().search(sid)` 重搜→移除原种子。
  - 非订阅源：`SearchChain().search_by_title` 跨索引器重搜→取 seeders 最多者→`DownloadChain().download_single` 添加→移除原种子。
  - 新增配置 `switch_source`（默认开）。
- 顺手修复致命 bug：`__notify` 旧式 `post_message(Notification(...))` 在 fork 新签名下会抛 channel 校验崩溃，导致所有通知失效，已改为关键字拆传。
- 部署：docker cp 到 `/app/app/plugins/stuckdownloadguard/`（仅内置路径，无 Market 副本）+ 清缓存 + 重启。容器内确认 `加载插件：StuckDownloadGuard 版本：1.1.0`，post_message 不再崩，切换方法均存在。
- 关键 API 事实：SearchChain.search_by_title 跨全部索引器返回 Context 列表；DownloadChain.download_single(context, torrent_content=enclosure, label=TORRENT_TAG) 高层添加；DownloadHistory 含 title/year/tmdbid/type 可回推媒体。
- 未实机触发真实0速度种子做端到端切换验证（需真实卡死任务），但导入/加载/语法/通知路径/表单/方法存在性均已验证。
