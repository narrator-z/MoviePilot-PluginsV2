## ChineseSubFinder 插件「没生效、无日志」根因与修复

用户在 NAS 上反馈该插件装上了但不生效、连日志都没有。逐行核对 MoviePilot v2.15.7 源码后定位：

### 根因（真实代码 bug）
- `TransferInfo` schema（app/schemas/transfer.py:113-143）在 v2.15.x **没有 `is_bluray` 也没有 `target_path` 字段**。
- 原 `download()` 直接读 `item_transfer.is_bluray` 和 `item_transfer.target_path` → 配置填好后会抛 `AttributeError`（被事件管理器捕获记 ERROR）。
- 更早的静默关卡（`_enabled=False` / `host`或`api_key`为空 / `event_data`为空）当初是 `return` 无日志 → 这正是用户"没日志"的症状来源。

### 修复（已提交 3469cbb，版本抬到 6.0.1）
- 目标路径改为从 `target_item.path` 或 `file_list_new` 推导；蓝光改为按路径含 `BDMV` 判定。
- `download()` 每个静默关卡改为 `logger.warning`/`logger.info`，启动 `init_plugin` 也加日志，便于在 NAS 日志一眼看到卡在哪一步。
- 事件机制本身正确：`TransferComplete` 事件携带 `{"mediainfo","transferinfo"}`，键名匹配；`start()` 用 class 标识符 enable/disable handler，`__is_handler_enabled` 通过 `__qualname__` 解析同一 class 标识符，匹配一致——不是事件注册问题。

### 排查结论（对用户）
"无日志"= 静默提前 return。更新后看 MoviePilot 日志即可定位：未启用 / host·token 未配 / 收到事件并调用 CSF。市场此前"取不到仓库"是另一独立问题（疑似 GitHub 镜像 404 缓存）。

## 可复用经验
- MoviePilot V2 插件插件写 `TransferComplete` 监听时，**不要依赖 `TransferInfo.is_bluray`/`target_path`**；路径用 `target_item.path` 或 `file_list_new`，蓝光按 BDMV 判定。
- 插件 handler 内的提前 return 一定要打日志，否则"不生效无日志"极难排查。

## 新增 NeoDBSource 插件（对标 imdbsource 的 NeoDB 数据源）

参考 wumode/MoviePilot-Plugins 的 imdbsource，新建 `plugins.v2/neodbsource/`（__init__.py + neodbhelper.py），让探索/推荐/媒体识别支持 NeoDB。版本 1.0.0，已加入 package.v2.json 与 README，图标 icons/neodb.png（纯 Python zlib 生成）。

### NeoDB API 实测要点（直接用 curl 探明，docs 只给 OAuth 概览）
- 公开 API 无需鉴权：`GET /api/catalog/search?query=<词>&category=<movie|tv|book|game|music|anime>&page=`；`GET /api/trending/game/`（公开）；`GET /api/{category}/{uuid}`（**无尾部斜杠**，带斜杠 404）。
- 搜索参数名是 `query` 不是 `q`，且必填非空（空串/空格 → 400）。
- 条目**没有** `tmdb_id` 字段；tmdb 映射藏在 `external_resources[].url` 里（如 `themoviedb.org/movie/27205`），需用正则提取。
- 类别枚举：book/movie/tv/music/game/podcast/performance；anime 在 NeoDB 归 tv。

### MoviePilot 媒体ID前缀关键机制（影响 neodb: 回链设计）
- `app/utils/media.py:normalize_media_source` 对未知前缀返回**字符串本身**（非 None）。故 `neodb:movie.uuid` 经 `parse_media_key` 得到 ("neodb","movie.uuid") 均为真 → 详情页直接以 `source="neodb"` 调 `recognize_media`，**不走** `MediaRecognizeConvert` 广播分支（该分支仅在前缀解析为 falsy 时触发）。
- 因此 `neodb:` 回链必须在被劫持的 `recognize_media` 里处理：`kwargs` 带 `source=="neodb"` 且 `mediaid` 时，按 `category.uuid` 取详情并构建 MediaInfo。imdbsource 的 `imdb:` 同理（MP 也无原生 imdb 字段，靠 recognize 补丁与 MediaRecognizeConvert 双写兜底）。
- `MediaInfo`（app/core/context.py）只有 tmdb_id/imdb_id/douban_id/bangumi_id，**无 neodb_id**；用 `source="neodb"` + `media_id="category.uuid"` 承载 neodb 标识，`to_dict()` 据此生成 `mediaid_prefix="neodb"`。
- `get_api` 端点返回值会被 FastAPI 默认序列化（MP 用 `add_api_route(**api)` 不加 response_model）→ 必须返回 `media.to_dict()` 的 dict 列表，不要直接返回 `context.MediaInfo` dataclass（MP 内部 discover 端点也是这么做的）。

### 复用模式（以后写同类"外部数据源"插件可直接套）
1. 三个事件钩子：`DiscoverSource`（注册 DiscoverMediaSource，filter_ui 提供类别 chips + 关键词 model="q"）、`RecommendSource`（注册 RecommendMediaSource，api_path 可内嵌 `?category=&q=`）、`MediaRecognizeConvert`（neodb:→tmdb 兜底）。
2. recognize 补丁：复制 imdbsource 的 `patched_recognize_media`/`_extract_method_kwargs` 模板，auxiliary 模式替换 `ChainBase.recognize_media`，hijacking 模式走 `get_module`。
3. 过滤 UI 的关键词框用 `VTextField model="q"`，探索页会把其值作为查询参数传给插件 API。

用户再次反馈插件市场看不到本仓库、安装不了。已通过 GitHub API/raw 远端核查（无 NAS SSH 权限）：

### 已确认的确定性事实

- `get_plugins` 拉 `package.v2.json`（raw 文件）→ `__request_with_fallback` 先试 `GITHUB_PROXY` 镜像站。

- 故：若用户所配镜像对该小仓库返回 404（早期 404 缓存未刷新 / 未被镜像收录），Market 永远看不到该仓库 → "不显示"，进而"安装不了"。完美解释「别的仓库正常、就你的不行」（大仓库镜像有 200 缓存）。

### 解决方案（按推荐）
1. **换/配镜像**：MP 设置 → 系统 → GitHub 镜像，换成对该仓库返回 200 的（如 ghproxy.net）。
2. **本地仓库（最稳，绕开 GitHub）**：把仓库 clone 到 NAS 本地绝对路径，设置 `PLUGIN_LOCAL_REPO_PATHS=/path/MoviePilot-PluginsV2`，Market 用 `local://` 前缀直接从磁盘读。
3. **直连**：若 NAS 网络允许，清空镜像试直连。
- 注：发 GitHub Release 只解决"安装"、不解决"列表不显示"（列表仍走 raw 镜像），非首选。

## NeoDBSource v1.0.2：点击报错「未识别到媒体信息」+ 分类/筛选器 + 安全图片域名（用户第四轮回馈）

### ① 安全图片域名（结论：不用加，加不了是因为已覆盖）
- 图片代理 `app/api/endpoints/system.py:fetch_image` → `SecurityUtils.is_safe_image_url_async`：先查 `SECURITY_IMAGE_DOMAINS` 白名单，**公网域名**还会过 DNS 检查（`evaluate_url_safety_async` 公网 IP 直接放行）。即 neodb.social 作为公网域名本就自动放行，无需加白名单。
- 插件 `init_plugin` 已把 neodb.social 显式 append 进 `settings.SECURITY_IMAGE_DOMAINS`（运行时白名单）。
- NAS 日志实证：图片代理拦截只命中 `bfjy2024.github.io`、`hcplantern.top.png`、`github.com.png`（reason=domain_not_allowed，且 host 为空——是别的 URL 解析问题），**没有任何 neodb.social 被拦**。所以 NeoDB 封面在探索页/详情页其实正常显示，「加不了」是 UI 持久化与运行时注入不一致造成的错觉，功能上不需要手动加。

### ④ 点击报错根因（核心修复）
- MP 媒体详情页 `app/api/endpoints/media.py` 的 `media_info` 端点：`parse_media_key("neodb:tv.uuid")` → `("neodb","tv.uuid")`（normalize_media_source 对未知前缀返回字符串本身）→ 直接调 `async_recognize_media(source="neodb", mediaid="tv.uuid")`。
- 这条识别路径**只在插件把 recognize 方法注册为模块、或 auxiliary 模式给 ChainBase 打补丁时才被插件处理**。旧实现把处理放在 `recognize_media` 子开关（默认 False）+ ChainBase 补丁里 → 子开关没开就没人处理 neodb 源 → 返回空 → 前端报「未识别到媒体信息」。
- **修复**：`get_module()` 在插件 `_enabled` 时即返回 `recognize_media`/`async_recognize_media`（不再 gate 在 hijacking 模式）；方法内仅当 `source=="neodb" and mediaid` 时回查 NeoDB 构造 MediaInfo，**其余来源一律返回 None 交还核心模块**，绝不覆盖 TMDB/豆瓣正常识别。删除 ChainBase 补丁与 `recognize_media`/`recognition_mode` 子开关（及 `_extract_method_kwargs`/`_restore_original`）。
- 同时给 `item_to_mediainfo` 补 `douban_id`/`imdb_id` 提取（正则 `_DOUBAN_RE`/`_IMDB_RE`），有外链的条目详情更完整、可订阅。
- 容器实证：trending tv 55 条，type 分布 TVShow:49/TVSeason:6；Hacks 抽出 tmdb=124101、imdb=tt11815682，cover_host=neodb.social。

### ② 分类 + 类型筛选器
- `neodb_filter_ui` 类别 chips 精简为 **电影/剧集/动画**（去掉图书/游戏/音乐）。
- 每个类别下用 MP 的 `show` 表达式挂「类型」子筛选（电影→电影；剧集/动画→电视剧 TVShow / 单季 TVSeason）+「排序」（热门/高分）。`neodb_discover` 新增 `mtype`/`sort` 参数做客户端二次筛选与按评分排序。
- **限制**：NeoDB 公开 API 只支持 `category`+`query`，**没有 genre 维度**，所以"类型"目前是条目的 `type` 子类型 + 排序，不是题材/类型流派。若用户要 genre 级筛选，需 NeoDB 后续开放或客户端按 tags 过滤（暂未做）。
