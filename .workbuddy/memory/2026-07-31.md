## ChineseSubFinder 插件「没生效、无日志」根因与修复

用户在 NAS 上反馈该插件装上了但不生效、连日志都没有。逐行核对 MoviePilot v2.15.7 源码后定位：

### 根因（真实代码 bug）
- `TransferInfo` schema（app/schemas/transfer.py:113-143）在 v2.15.x **没有 `is_bluray` 也没有 `target_path` 字段**。
- 原 `download()` 直接读 `item_transfer.is_bluray` 和 `item_transfer.target_path` → 配置填好后会抛 `AttributeError`（被事件管理器捕获记 ERROR）。
- 更早的静默关卡（`_enabled=False` / `host`或`api_key`为空 / `event_data`为空）当初是 `return` 无日志 → 这正是用户"没日志"的症状来源。

### 修复（已提交 3469cbb，版本抬到 6.0.1）
- 目标路径改为从 `target_item.path` 或 `file_list_new` 推导；蓝光改为按路径含 `BDMV` 判定。
- `download()` 每个静默关卡改为 `logger.warning`/`logger.info`，启动 `init_plugin` 也加日志，便于在 NAS 日志一眼看到卡在哪一步。
- 事件机制本身正确：`TransferComplete` 事件携带 `{"mediainfo","transferinfo"}`，键名匹配；`start()` 用 class 标识符 enable/disable handler，`__is_handler_enabled` 通过 `__qualname__` 解析同一 class 标识符，匹配一致——不是事件注册问题。

### 排查结论（对用户）
"无日志"= 静默提前 return。更新后看 MoviePilot 日志即可定位：未启用 / host·token 未配 / 收到事件并调用 CSF。市场此前"取不到仓库"是另一独立问题（疑似 GitHub 镜像 404 缓存）。

## 可复用经验
- MoviePilot V2 插件插件写 `TransferComplete` 监听时，**不要依赖 `TransferInfo.is_bluray`/`target_path`**；路径用 `target_item.path` 或 `file_list_new`，蓝光按 BDMV 判定。
- 插件 handler 内的提前 return 一定要打日志，否则"不生效无日志"极难排查。

## 新增 NeoDBSource 插件（对标 imdbsource 的 NeoDB 数据源）

参考 wumode/MoviePilot-Plugins 的 imdbsource，新建 `plugins.v2/neodbsource/`（__init__.py + neodbhelper.py），让探索/推荐/媒体识别支持 NeoDB。版本 1.0.0，已加入 package.v2.json 与 README，图标 icons/neodb.png（纯 Python zlib 生成）。

### NeoDB API 实测要点（直接用 curl 探明，docs 只给 OAuth 概览）
- 公开 API 无需鉴权：`GET /api/catalog/search?query=<词>&category=<movie|tv|book|game|music|anime>&page=`；`GET /api/trending/game/`（公开）；`GET /api/{category}/{uuid}`（**无尾部斜杠**，带斜杠 404）。
- 搜索参数名是 `query` 不是 `q`，且必填非空（空串/空格 → 400）。
- 条目**没有** `tmdb_id` 字段；tmdb 映射藏在 `external_resources[].url` 里（如 `themoviedb.org/movie/27205`），需用正则提取。
- 类别枚举：book/movie/tv/music/game/podcast/performance；anime 在 NeoDB 归 tv。

### MoviePilot 媒体ID前缀关键机制（影响 neodb: 回链设计）
- `app/utils/media.py:normalize_media_source` 对未知前缀返回**字符串本身**（非 None）。故 `neodb:movie.uuid` 经 `parse_media_key` 得到 ("neodb","movie.uuid") 均为真 → 详情页直接以 `source="neodb"` 调 `recognize_media`，**不走** `MediaRecognizeConvert` 广播分支（该分支仅在前缀解析为 falsy 时触发）。
- 因此 `neodb:` 回链必须在被劫持的 `recognize_media` 里处理：`kwargs` 带 `source=="neodb"` 且 `mediaid` 时，按 `category.uuid` 取详情并构建 MediaInfo。imdbsource 的 `imdb:` 同理（MP 也无原生 imdb 字段，靠 recognize 补丁与 MediaRecognizeConvert 双写兜底）。
- `MediaInfo`（app/core/context.py）只有 tmdb_id/imdb_id/douban_id/bangumi_id，**无 neodb_id**；用 `source="neodb"` + `media_id="category.uuid"` 承载 neodb 标识，`to_dict()` 据此生成 `mediaid_prefix="neodb"`。
- `get_api` 端点返回值会被 FastAPI 默认序列化（MP 用 `add_api_route(**api)` 不加 response_model）→ 必须返回 `media.to_dict()` 的 dict 列表，不要直接返回 `context.MediaInfo` dataclass（MP 内部 discover 端点也是这么做的）。

### 复用模式（以后写同类"外部数据源"插件可直接套）
1. 三个事件钩子：`DiscoverSource`（注册 DiscoverMediaSource，filter_ui 提供类别 chips + 关键词 model="q"）、`RecommendSource`（注册 RecommendMediaSource，api_path 可内嵌 `?category=&q=`）、`MediaRecognizeConvert`（neodb:→tmdb 兜底）。
2. recognize 补丁：复制 imdbsource 的 `patched_recognize_media`/`_extract_method_kwargs` 模板，auxiliary 模式替换 `ChainBase.recognize_media`，hijacking 模式走 `get_module`。
3. 过滤 UI 的关键词框用 `VTextField model="q"`，探索页会把其值作为查询参数传给插件 API。

## NeoDBSource「点击仍 500 / 没图」彻底收尾（用户第五轮回馈，本会话续）

用户回「还是没有图、点击后还是报错 404 / 出错啦 / 无法获取到媒体信息」。SSH 上 NAS 逐层复现定位，两个真正根因都已修并容器实测通过。

### 根因 A：点击详情 500（MediaType year 类型错配）
- 详情端点 `app/api/endpoints/media.py:media_info` 返回 `MediaInfo` 时带 `response_model` 校验；`schemas.MediaInfo.year` 字段类型是 **str**，而 `neodbhelper.item_to_mediainfo` 写的是 `mi.year = int(year)`（整型）→ `fastapi.ResponseValidationError: year input should be a valid string` → **HTTP 500**（不是 404，前端「出错啦」即此）。
- `MediaType` 枚举值是中文（`MediaType.MOVIE.value == "电影"`），端点 `MediaType(type_name)` 要求中文；用英文 `MOVIE` 测会 `ValueError`——之前误判 500 是测试用错 type_name 造成的假象，真 500 来自 year。
- **修复**：`mi.year = str(year)`。已 docker cp 进容器 `/app/.../neodbhelper.py` 两份（见下"根因 B"的路径），重启后实测：`neodb:movie.7LXcnrlommYYE4oSom6OXI` + `type_name=电影` → **HTTP 200**，title=Spider-Man、tmdb=324857、poster/backdrop 均有值。

### 根因 B：分类切换后筛选器把列表筛空（且内置插件覆盖 Market 副本）
- `neodb_discover` 的类型二次筛选旧逻辑：`items = [it for it in items if it.get("type") == mtype]`，**没有按当前 category 校验 mtype 合法性**。结果：在电影标签选了 `Movie` 再切到剧集标签，残留 `mtype="Movie"` 把全部 TV 条目筛掉 → 列表空。
- **更重要的隐藏坑**：用户 fork 镜像 `ghcr.io/narrator-z/moviepilot:latest` 本身已在 `/app/app/plugins/neodbsource/` **内置了一份 neodbsource（v1.0.2）**，与 Market 装的 `/config/plugins/neodbsource/` 同时存在。两者 import 名都是 `app.plugins.neodbsource`，**实际加载的是内置那份**（Market 副本被 shadow）。所以只改 Market 副本不生效——之前分类筛选修复一直"没生效"的真正原因在此。
- **修复**：直接 patch 容器内 **`/app/app/plugins/neodbsource/__init__.py`**（正在加载的那份）的筛选块，按 category 校验：
  ```
  valid_types = {"movie":{"Movie"}, "tv":{"TVShow","TVSeason"}}.get(api_category, set())
  if mtype not in valid_types: mtype = None
  if mtype: items = [it for it in items if it.get("type") == mtype]
  ```
  同时把同一份同步到 `/config/plugins/neodbsource/__init__.py`（保持一致）。重启实测：`cat=tv,mtype=Movie`（切换残留）→ 55 条不空；`tv+TVShow`→47、`tv+TVSeason`→8、`movie+Movie`→60。

### 图片：实测「能显示」，之前的"没图"是 500 连带 + 测试假象
- 图片代理 `IMAGE_PROXY_ALLOWED_PRIVATE_RANGES` 在用户 `app.env` **已正确配置**为 `["198.123.0.0/16","fdfe:dcba:9876::/64"]`，恰好覆盖 clash fake-ip 给 neodb.social 解析出的 `198.123.0.159`/`fdfe:dcba:9876::9f`。`is_safe_image_url_async` 先过白名单再过 DNS 私网放行——neodb.social 安全校验 **safe=True**。
- 实测 fetch：neodb 真实封面 `https://neodb.social/m/item/imdb/...jpg` → **471KB image/jpeg 成功**；doubanio 背景图 48690B 成功；fanart 459KB 成功。即探索页缩略图（cover=neodb.social）、详情页背景（doubanio）都正常。
- 之前"Blocked unsafe image URL / reason=non_global_dns_result"是我测试脚本把 `allowed_private_ranges=None` 硬传进去导致的假象，非真实端点行为（真实端点传 `settings.IMAGE_PROXY_ALLOWED_PRIVATE_RANGES`）。
- 详情页海报之前指向 `image.tmdb.org/.../sxubDbvo0FhMe9...jpg` 该路径 TMDB 已 404（陈旧 poster_path，非系统性）；刷新查 TMDB 拿到有效 poster（`/iiZZdoQBEYBv6...jpg`）→ 200 672KB，证明 image.tmdb.org 本身可达。**为兜底**：在 `item_to_mediainfo` 把 `poster_path` 也设为 neodb 封面（列表卡片优先取 poster_path，此前为 None 才显空白），详情页仍由核心 obtain_images 用 TMDB/fanart/douban 覆盖，TMDB 失效时 neodb 封面兜底。实测列表 60/60 条 poster_path 已填充。

## NeoDBSource v1.0.3：丰富探索筛选器（用户第六轮回馈）

用户：分类太少，参考 IMDb/豆瓣把筛选条件加上，现在只能显示热门和高分榜单、看不到所有的。

### NeoDB 公开 API 约束（用 OpenAPI schema + curl 探明，决定能加什么）
- 唯一公开浏览流：`GET /api/trending/{category}/`（category∈book/movie/music/game/performance/podcast/tv；anime 归 tv）。**没有** `/api/ranking/` 与 `/api/discover/` 端点（均 404）。
- `/api/trending/tag/` 无 `tag` 参数时返回 **40 个标签名字符串**（类型/地区/年代如 科幻/动作/日本/美国/2026…）；带 `tag=科幻` 仍返回同样的标签名列表（参数被忽略），**不是按标签过滤的条目流** → 无法做 genre/地区/年代筛选。
- trending 列表载荷 **不含 `year` 与 `tags`**（抽 60 条 movie / 55 条 tv，year 0/60 填充、tags 全空）→ 客户端也无法按年代/类型派生筛选。
- 结论：能做的"筛选条件"只有基于该 trending 流在客户端派生的 **排序** 与 **评分阈值**（列表载荷自带 `rating`/`rating_count`）。

### 改动（已 docker cp 部署 + 重启验证）
- `neodb_filter_ui` 新增两组 chips：
  - **榜单(sort)**：热门 hot / 高分 rating（按 rating 降序）/ 最多评分 rating_count（按 rating_count 降序）/ 按标题 title（A–Z）。（原只有 热门/高分 2 个）
  - **评分(min_rating)**：全部 0 / 8分+ / 7分+ / 6分+（客户端按 `rating` 阈值过滤）。
  - 保留：分类 电影/剧集/动画、类型子筛选(随分类 show 联动)、搜索 q。
- `neodb_discover` 新增 `min_rating` 参数；`sort` 扩展 `rating_count`/`title` 分支；先 mtype 过滤→评分过滤→排序。
- `filter_params` 默认补 `min_rating:"0"`；插件信息 VAlert 说明 NeoDB 公开 API 限制（无排行榜/最新端点、无年代/类型标签）。
- 版本号 `__init__.py` plugin_version 1.0.2→1.0.3（**package.v2.json 也要同步升**）。
- 容器实测：movie hot/rating/rating_count/title 均 200 且顺序正确；min_rating=8→14 条、=6→55 条；tv TVShow→47、anime→55、search spider→20，全部 200。

### 关于"分类太少"的解释（给用户）
NeoDB 公开 API 的影视分类本质就是 movie/tv（anime 归 tv），book/game/music 等非影视不纳入 MP 探索；genre/地区/年代筛选受 API 限制（无 ranking/discover、列表无 year/tags）暂时做不到，已在插件说明里写明。真正"看不到所有的"靠 按标题排序 + 翻页 + 评分=全部 解决。
