# 2026-08-02 工作日志

## ChineseSubFinder 报错排查与修复（→ v6.0.2）
- 用户报「一直报错」两类：
  1. ERROR `调用 ChineseSubFinder API 失败！HTTP 500：open ... .nfo: no such file or directory`
  2. WARNING `【ChineseSubFinder】发送通知失败：1 validation error for Notification channel`
- 根因：
  - #2 = fork 把 `_PluginBase.post_message` 签名从「接收 Notification 对象」改成「拆传 channel/mtype/title 关键字」，插件仍旧式 `post_message(Notification(...))`，Notification 被当成 channel 触发枚举校验失败。
  - #1 = 时序竞态：MP `TransferComplete` 立刻调 CSF add-job，但 Emby/Jellyfin 还没生成 `.nfo`（CSF 靠 .nfo 取 id）；`.nfo` 晚约 1 分钟出现后 CSF 自会下好字幕（实测 .zh.srt/.zh.ass 都在）。
- 修复：
  - `__notify` 改为 `post_message(mtype=..., title=..., text=..., source=...)` 关键字拆传。
  - `__request_csf` 改为后台 daemon 线程 + 对 5xx/网络异常最多 5 次(间隔20s)重试；仅 4xx/重试耗尽才记 ERROR+通知；瞬时仅 INFO「暂未就绪…重试」。
  - 版本升 6.0.2（plugin + package.v2.json 双字段一致）。
- 部署：仅 fork 内置 `/app/app/plugins/chinesesubfinder/`（无 /config 副本），docker cp + 清 __pycache__ + restart。
- 验证：容器内 `加载插件：ChineseSubFinder 版本：6.0.2` 无失败；`MessageChain.post_message(mtype=..., title=..., text=..., source=...)` 实测不崩 channel 校验。

## 关键 fork 约定（写入 MEMORY.md）
